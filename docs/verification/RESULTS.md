## 구현한 기능

- 일반 로그인과 서버 측 비밀번호 해시 확인, 계정·IP 요청 제한.
- Spring Security CSRF와 요청별 인증·인가, 보호된 실제 설정 저장.
- Spring Session Redis 저장소를 이용한 A·B 서버 세션 공유.
- 유휴·절대 만료와 고정 로그인 유지 종료 시각.
- 유지 토큰 해시 저장, 복원 시 교체, 동시 요청 1회 성공, 이전 토큰 재사용 거부.
- 최근 비밀번호 재확인과 세션 식별자 교체.
- 현재 기기·다른 기기·전체 기기 폐기와 사용자 인증 버전 관리.
- 만료된 세션에서 로그아웃해도 유지 자격정보를 DB에서 폐기하는 처리.
- DB 폐기와 정리 작업의 같은 트랜잭션 저장, Redis 정리 재시도.
- 원문 인증정보를 제외한 실행 기록, 실제 파일·행에 연결한 소스 보기.
- 실제 Redis TTL·최근 활동 시각과 DB 기록의 별도 관찰.
- 브라우저에서 직접 실행할 수 있는 전체 회귀 검증.

## 장애 검증의 구분

Redis·DB 연결 장애는 앱과 실제 저장소 사이의 TCP 경로를 차단해 재현했다. DB 활성화 직전과 폐기 직후의 실패는 지정한 서버 처리 지점에 주입했다. 응답 유실은 서버 처리 완료 뒤 실제 브라우저 응답 연결을 끊어 재현했다.

Redis는 실제 프로세스를 종료·재시작한 뒤 해당 실행의 세션을 삭제했다. 앱 A도 실제 Java 프로세스를 종료하고 B에서 기존 인증을 확인했다. 오래된 Redis 해시를 복구한 경우에도 DB 폐기 상태가 옛 쿠키의 접근을 차단했다.

유지 토큰 교체 후 새 응답을 받지 못한 경우 이전 토큰을 되돌리지 않고 비밀번호 재로그인을 요구한다. 데이터 조회 실패는 확인 불가로 표시하며, 만료·삭제 완료와 구분한다.

## 실행 환경과 검증 범위

현재 결과는 Windows의 실제 PostgreSQL 17.11과 Redis 7.4.3 서버에서 얻었다. Redis는 개발용 Windows 포트이며 출처와 체크섬은 실행 스크립트에 고정했다. [환경 기록](ENVIRONMENT.md)

Docker Compose 설정은 구문 검사를 통과했다. 현재 Docker 엔진의 기동 오류로 Linux 컨테이너 실행은 수행하지 않았으며, 이를 Windows 실행 결과로 대체 표기하지 않는다. 공개 배포·운영 부하 수용량은 이번 검증 범위에 포함하지 않는다.

인증 쿠키, 비밀번호, CSRF 원문을 결과 보고서에 저장하지 않는다. 실제 브라우저 재실행에는 임시 프로필을 사용하고 시험 후 제거한다. [실행과 재검증 안내](../../README.md)
